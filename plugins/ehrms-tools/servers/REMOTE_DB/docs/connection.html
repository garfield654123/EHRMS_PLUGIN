ehrms-custom-mcp 連線原理

工程師電腦和客戶機器不會直接互連。兩邊都往外連到 relay，靠客戶端畫面上的 6 碼配對碼配成一對。連客戶資料庫的是客戶機器上的 EHRMS_Connect.exe，帳密只留在那台機器的記憶體裡。

目前為測試階段。內容依 2026-11-04 的 servers/REMOTE_DB 程式與 SPEC.md 整理。

四段連線

連線發起方通訊方式加密連線行為
mcp_server.py → relay.py工程師電腦WebSocket，ws://127.0.0.1:8770無，只在本機每筆查詢開一條新連線，等結果最多 60 秒
zrok2 → zrok 節點工程師電腦zrok 分享 public:ehrms-relay，把本機 8770 公開出去由 zrok 處理關機或程序結束後，所有客戶端都連不上
EHRMS_Connect.exe → zrok 節點客戶機器wss://ehrms-relay.shares.zrok.io，port 443TLS，在 zrok 節點解開保持長連線，每 20 秒 ping，60 秒沒回應算斷線，斷線後每 5 秒以同一配對碼重連
EHRMS_Connect.exe → 客戶 MSSQL客戶機器ODBC，驅動 {SQL Server}；DB 主機預設 .（本機）連線字串未設定加密每筆查詢開新連線，連線逾時 10 秒、查詢逾時 30 秒

客戶機器的條件

需要

  • 工程師能用 Splashtop 或 AnyDesk 操作這台機器
  • 能連到客戶 MSSQL，並有資料庫帳號，預設帳號 ehrms
  • 能往外連 port 443
  • 帳號要有 SHOWPLAN 權限，否則查詢都會被拒絕

不需要

  • 開 inbound port：客戶端只主動往外連
  • 安裝程式：單一 exe，約 9 MB
  • 安裝資料庫驅動：{SQL Server} 是 Windows 內建
  • 較新的作業系統：exe 以 Python 3.8 打包，以支援 Windows Server 2012、2008 R2

連不上時怎麼判斷

看到的訊息原因處理方式
資料庫連線失敗帳密、DB 主機或資料庫名稱有誤核對輸入值，資料庫可按「偵測」列出
[Errno 11002] getaddrinfo failed客戶機器 DNS 解析不到中繼網址換新版 exe，會自動改連 agent.ini 的 relay_ips
CERTIFICATE_VERIFY_FAILED舊版 Windows 的根憑證過舊目前版本已內附 certifi 根憑證；舊版要換新
Error loading Python DLLexe 不是用 Python 3.8 打包，舊版 Windows 無法執行用 Python 3.8 重新打包
無法連到 relay工程師電腦的 relay 沒有在執行執行 start-relay.ps1
找不到配對碼 … 的客戶端exe 已關閉或中斷，或 1 小時沒有查詢而自動中斷在客戶端重新登入，改用新的配對碼
要經 Proxy 才能上網客戶端目前不支援 Proxy改回提供 SQL，請客戶端執行後貼回
